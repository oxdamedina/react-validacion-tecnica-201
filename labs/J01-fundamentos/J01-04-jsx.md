# J01-04 — JSX

[← Página anterior](J01-03-entorno.md) · [Siguiente página →](J01-05-componentes.md)

TSX parece HTML dentro de TypeScript. Lo que va entre llaves es una expresión: `{item.titulo}` pinta el título del dato. Sin llaves, se pinta la palabra `item.titulo`. `class` de HTML aquí es `className`. El estado de una ficha solo puede ser `pendiente`, `revisado` o `rechazado`.

## Demostración

### Objetivo

Distinguir una expresión de un texto fijo, y ver que un estado fuera del tipo no compila.

### Código de partida

La ficha ya pinta el título con llaves. Si `Tarjeta.tsx` no es esta, pégala. `datos.ts` tiene seis objetos. E-104 está `rechazado`.

```tsx
import type { Entregable } from "../modelo"

interface TarjetaProps {
  item: Entregable
  textoBoton?: string
  alMarcar: (id: string) => void
}

export default function Tarjeta({
  item,
  textoBoton = "Anotar",
  alMarcar,
}: TarjetaProps) {
  return (
    <article>
      <p>{item.titulo}</p>
      <p>
        {item.id} · {item.proveedor}
      </p>
      <p className={`estado ${item.estado}`}>{item.estado}</p>
      {item.estado === "pendiente" ? <p>Falta revisión</p> : null}
      <button type="button" onClick={() => alMarcar(item.id)}>
        {item.estado === "revisado" ? "Hecho" : textoBoton} {item.id}
      </button>
    </article>
  )
}
```

```tsx
{ id: "E-104", titulo: "Inventario de componentes", proveedor: "Este", estado: "rechazado" },
```

### 1 — Llaves y tipo

**Dónde:** `Tarjeta.tsx` y `datos.ts`.

**Qué haces:**

1. Quita las llaves del título y deja el texto `item.titulo`. Guarda. Mira la ficha.
2. Devuelve `{item.titulo}`.
3. En `datos.ts`, cambia el estado de E-104 a `"listo"`. Mira Problems, no solo el navegador.
4. Restaura `"rechazado"`.
5. En la pastilla, escribe `class` en vez de `className`. Restaura `className`.

**Experimento:** en la línea del id, quita las llaves de `{item.id}` y déjalas en `{item.proveedor}`.

→ Se lee la palabra `item.id` y, al lado, `Este` o el proveedor real. Vuelven las dos expresiones. Con `"listo"`, Problems marca `datos.ts`. Con `class`, marca el atributo.

**Validación:**

- Las fichas muestran títulos de entregable, no la palabra `item.titulo`.
- E-104 está en `"rechazado"`.
- El atributo es `className`.

## Comprueba tu entendimiento

**Texto fijo junto a la expresión**
La línea `E-101 · Norte` tiene el punto medio fuera de las llaves.
→ `·` es texto. `item.id` y `item.proveedor` son expresiones.

## Reto

### 1 — Una expresión que no es un campo

Bajo el título, añade `<p>{item.id.length}</p>`. Mira el número. Borra el párrafo.

## Errores frecuentes

| Síntoma | Causa probable | Cómo arreglarlo |
|---------|----------------|-----------------|
| Se ven las llaves en la página | Quedaron dentro de un string | `{item.titulo}`, no `"{item.titulo}"` |
| `"listo"` no se marca | El campo `estado` es `string` o `any` | En `modelo.ts` es `EstadoEntregable` |

## Laboratorio

La demostración tocó las llaves del título y el tipo del estado. Aquí pintas un número calculado.

### Objetivo

Mostrar cuántas fichas hay, con una expresión, sin escribir el 6 a mano.

### Código de partida

`App` recorre `visibles` o `entregables`. Si no hay lista en `App`, usa `entregables` de `datos.ts`.

### Qué haces

1. Debajo del `<h1>`, pega el párrafo.
2. Escribe `Norte` si hay filtro. El número baja.
3. Quita las llaves y deja `lista.length`. Lees esa palabra.
4. Restaura las llaves y el párrafo.

```tsx
const lista = visibles
```

Si tu archivo no tiene `visibles`, `const lista = entregables`.

```tsx
<p>{lista.length} fichas</p>
```

→ Con la caja vacía se lee «6 fichas». Sin llaves se lee la palabra `lista.length`. Con las llaves, `Norte` cambia el número.
