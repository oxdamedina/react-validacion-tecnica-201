# J01-02 — SPA

[← Página anterior](J01-01-react.md) · [Siguiente página →](J01-03-entorno.md)

En una aplicación tradicional, cada clic pide un documento nuevo. Aquí el navegador carga `index.html` una vez. La caja y la pastilla cambian sobre ese mismo documento. Al recargar, lo marcado vuelve al valor inicial: vivía en memoria.

## Demostración

### Objetivo

Comprobar que filtrar y marcar no piden otro documento.

### Código de partida

Pega estos dos archivos y recarga `http://localhost:5173`. Hay seis fichas y una caja «Buscar». El botón de una pendiente dice «Anotar» y, al pulsarlo, «Hecho».

`bandeja/src/App.tsx`

```tsx
import { useState } from "react"
import { entregables } from "./datos"
import type { Entregable } from "./modelo"
import Tarjeta from "./componentes/Tarjeta"

export default function App() {
  const [texto, setTexto] = useState("")
  const [items, setItems] = useState<Entregable[]>(entregables)

  const visibles = items.filter((item) => {
    const blob = `${item.titulo} ${item.proveedor} ${item.id}`.toLowerCase()
    return blob.includes(texto.toLowerCase())
  })

  function marcar(id: string): void {
    setItems((lista) =>
      lista.map((item) =>
        item.id === id ? { ...item, estado: "revisado" } : item,
      ),
    )
  }

  return (
    <main>
      <h1>Bandeja de entregables</h1>
      <label htmlFor="filtro">Buscar</label>
      <input
        id="filtro"
        value={texto}
        onChange={(evento) => setTexto(evento.target.value)}
      />
      {visibles.length === 0 ? <p>Ningún entregable coincide.</p> : null}
      <ul className="lista">
        {visibles.map((item) => (
          <li key={item.id}>
            <Tarjeta item={item} alMarcar={marcar} />
          </li>
        ))}
      </ul>
    </main>
  )
}
```

`bandeja/src/componentes/Tarjeta.tsx`

```tsx
import type { Entregable } from "../modelo"

interface TarjetaProps {
  item: Entregable
  textoBoton?: string
  alMarcar: (id: string) => void
}

export default function Tarjeta({
  item,
  textoBoton = "Anotar",
  alMarcar,
}: TarjetaProps) {
  return (
    <article>
      <p>{item.titulo}</p>
      <p>
        {item.id} · {item.proveedor}
      </p>
      <p className={`estado ${item.estado}`}>{item.estado}</p>
      {item.estado === "pendiente" ? <p>Falta revisión</p> : null}
      <button type="button" onClick={() => alMarcar(item.id)}>
        {item.estado === "revisado" ? "Hecho" : textoBoton} {item.id}
      </button>
    </article>
  )
}
```

### 1 — Un documento, varios pintados

**Dónde:** el navegador, pestaña Network. Filtra por Doc si el panel lo permite.

**Qué haces:**

1. Recarga. Cuenta la petición del documento HTML.
2. Escribe `Norte` en «Buscar».
3. Borra el texto.
4. Pulsa «Anotar» en una ficha que siga pendiente.
5. Mira la dirección de la página.

**Experimento:** recarga otra vez después de marcar.

→ Al teclear y al pulsar no se pide otro HTML. La dirección sigue en `/`. Al recargar, el documento se pide de nuevo y la ficha marcada vuelve a pendiente.

**Validación:**

- `Norte` deja a la vista fichas de ese proveedor.
- La pastilla cambia sin cambiar la URL.
- Tras recargar, la marca no sigue.

## Comprueba tu entendimiento

**Qué sí viaja por la red**
Abre `http://localhost:5173/entregables.json` en otra pestaña.
→ Es un archivo estático. La caja «Buscar» no lo vuelve a pedir en cada letra, aunque la app todavía pinte desde `datos.ts`.

## Reto

### 1 — La marca no es el documento

Marca E-101, copia la URL, ábrela en otra pestaña.
→ La otra pestaña muestra E-101 pendiente. Cada pestaña tiene su memoria.

## Errores frecuentes

| Síntoma | Causa probable | Cómo arreglarlo |
|---------|----------------|-----------------|
| Cada letra pide el HTML | No estás en la app de Vite, sino en un servidor de archivos | La URL es la de `npm run dev`, puerto 5173 |
| La marca sobrevive al recargar | Hay un `localStorage` que este laboratorio no usa | En esta bandeja, recargar restaura `datos.ts` o el JSON |

## Laboratorio

La demostración usó la caja y el botón. Aquí comparas un enlace con el botón.

### Objetivo

Ver que un `<a href>` pide otro documento y el botón de la ficha no.

### Código de partida

La bandeja con «Buscar» y las fichas. El botón tiene `type="button"`.

### Qué haces

1. En `App`, debajo del `<h1>`, pega este enlace.
2. Abre la pestaña Red. Pulsa el enlace. Mira si se pide un documento.
3. Vuelve atrás. Pulsa «Anotar» en una ficha. Mira la Red y la dirección.
4. Borra el enlace.

```tsx
<a href="/entregables.json">Ver JSON</a>
```

→ El enlace pide `/entregables.json`. «Anotar» no pide un documento: la dirección sigue en `/` y cambia la pastilla. Al borrar el enlace, la página queda como antes.
